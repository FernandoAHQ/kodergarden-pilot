# P1 baseline pilot: facilitator protocol

Status: ready to run; no classroom results have been collected by this implementation.

Use the original **Foundations** campaign for the baseline. Keep `Foundations — pilot v1` as a separate comparison; never combine their completion counts. Record the code revision and campaign revision from the session export. Do not silently change tasks, hints or timing between groups.

## Before learners arrive

- Prepare one device per learner or pair and the teacher projector. Record browser, device, input method and number of learners sharing it.
- Print the coded observation sheet (`pilot-observations.csv`) and blank squared paper. Use participant numbers, not names. Do not collect contact information.
- Assign the original tasks: First Steps, Turn the Corner, The Long Hallway, Meet Repeat. Keep a consistent 25-minute session window.
- Verify join/reconnect, drag/drop, undo, restore, run/reset, readable labels and projector trace controls on the actual devices. Record interface failures separately from conceptual mistakes.

## Fixed session sequence

1. **Orientation, 3 minutes.** Show dragging, a turn, undo and reset in an unrelated demonstration. Do not show the assigned route solution. Offer the same interface help to all learners.
2. **Sequence and turn, 6 minutes.** Before the first run, ask each learner to mark the predicted endpoint and arrow on paper. Record the prediction before revealing playback. Ask: “Which instruction changes the direction?” Record whether the learner answers without a conceptual hint.
3. **Repetition contrast, 8 minutes.** Solve The Long Hallway, then open Meet Repeat. Ask before running: “What is inside the repeated part? How many times does it run? How many moves happen altogether?” Accept speaking, pointing, drawing or writing. Record correctness of each response separately from successful execution and block count.
4. **Fresh check, 4 minutes.** On paper show Repeat 3 with a two-move body on a sufficiently long open route. Ask the total number of moves and final position. Do not present it as the same six-count task. No leading hints before recording the initial response.
5. **Explanation and wrap-up, 4 minutes.** Ask one learner-selected wrong attempt: “Where did it first differ from your prediction?” Record a quoted explanation only in ephemeral classroom notes if appropriate; the coded sheet needs only the rubric codes below. Export the Live pilot summary before ending the session.
6. **Delayed check, next class.** Repeat the two-move-body question with a changed count and orientation. Record the actual elapsed days. No model answer immediately before this check.

## Observation rubric

For each attempt record:

- Automated result: correct / incorrect / safety stop / not submitted. Keep active-case and case-family scope explicit.
- Prediction: correct / incorrect / unsure / missing; recorded before run or after viewing playback.
- Repeat explanation: identifies the body (yes/no/missing); distinguishes iteration count from total moves (yes/no/missing).
- Debug explanation: identifies first divergence (yes/no/missing); gives a causal repair explanation (yes/no/missing).
- Support: none / interface-only / conceptual / teacher-supplied solution / peer solution. Reading aloud or pointing access support is not automatically conceptual help.
- Observation: missing / supported / independent / transferred. Choose independent only after directly observing the learner's reasoning without conceptual help. Choose transferred only after the fresh or delayed case plus explanation supports it. A correct run or a shorter program alone is insufficient.
- Failure source: interface / concept / instruction wording / teacher workflow / network / uncertain. Record observable behavior instead of guessing a learner trait.

## Review gate

Review every recurring confusion and every interface failure before expanding the pilot. Compare correctness, before-run predictions and explanations separately. If most successful learners cannot explain the Repeat body/count distinction, revise that transition before adding harder loops. If interface failures prevent learners from expressing a solution, fix those controls before interpreting outcomes as conceptual weakness.

Use the revised pilot tasks in a later, clearly labeled comparison. Counterbalance task order where feasible and record prior exposure. This small pilot is a design diagnostic, not a validated learning-effect estimate or individual ability score. P2–P4 software availability does not waive this classroom gate.
