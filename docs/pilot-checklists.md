# Kodergarden Pilot Checklists

These checks intentionally remain manual where a real device, classroom network, or projector is part of the behavior. Record the device/browser, orientation, language, date, and pass/fail notes for each pilot run. Browser emulation is not a substitute for this checklist.

## Physical tablet QA

Test at least one Android tablet and, when available, one iPad. If only one platform is available, record that limitation in the pilot notes.

### Editor

- [ ] Drag a palette block to the root Program area.
- [ ] Reorder two root blocks.
- [ ] Drop a block inside Repeat.
- [ ] Drop a block inside If Path Ahead.
- [ ] Put Repeat inside If.
- [ ] Put If inside Repeat.
- [ ] Move a nested block back to root.
- [ ] Scroll the workbench and then drag a block.
- [ ] Delete a selected block.
- [ ] Undo and redo structural changes.
- [ ] Change the inline Turn direction.
- [ ] Change Repeat count using the numeric input.
- [ ] Confirm tap/select controls do not accidentally insert palette blocks.

### Simulation

- [ ] Run a program and stop/reset it.
- [ ] Confirm active-block highlighting follows execution.
- [ ] Confirm success feedback.
- [ ] Confirm wall/collision behavior.
- [ ] Confirm If Path Ahead shows true and false outcomes.

### Live Classroom

- [ ] Join with the six-digit code.
- [ ] Run locally, submit, edit, and resubmit.
- [ ] Temporarily disable Wi-Fi, restore it, and confirm reconnect.
- [ ] Refresh the student page and recover the same participant.
- [ ] Confirm the teacher can close submissions.
- [ ] Confirm the student moves to waiting/review state.
- [ ] Confirm the Live Submit button remains reachable in portrait and landscape.

### Device and language

- [ ] Tablet landscape.
- [ ] Tablet portrait.
- [ ] Rotate during an active challenge without losing the program.
- [ ] English UI.
- [ ] Spanish UI.

## Classroom projector QA

- [ ] Connect the teacher laptop to the classroom TV/projector.
- [ ] Open a Live lobby and stand at the back of the room.
- [ ] Verify the join code and joined count are readable.
- [ ] Verify the challenge title and objective are readable.
- [ ] Verify the programming submission count is readable.
- [ ] Review a list of 30–40 students and find a named student.
- [ ] Run a short selected program.
- [ ] Verify the student's name, visual program, active highlight, Pip movement, and success/failure are readable.
- [ ] Repeat in English and Spanish when relevant.
- [ ] Record checks at 1920×1080 and 1366×768; also test the physical projector's actual resolution.

## Teacher observation notes

- [ ] Can students join without help?
- [ ] Can they drag and connect blocks?
- [ ] Do they understand Run and Submit?
- [ ] Do they retry after failure?
- [ ] Do they distinguish Reset Simulation from Restore Program?
- [ ] Do they recognize why Repeat is useful?
- [ ] Do they watch classmates' playback?
- [ ] Where do they ask for help?
- [ ] Which challenge causes unexpected difficulty?

Do not tune the challenge sequence from assumptions; use these observations from real students.
